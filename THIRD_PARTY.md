## NG-GL4ES renderer (native, built from source at compile time, experimental)
- **Project:** NG-GL4ES (https://github.com/BZLZHH/NG-GL4ES), an OpenGL-over-OpenGL-ES renderer that uses glslang and SPIRV-Cross for shader conversion
- **License:** MIT. Full text in `app/src/main/assets/licenses/ng-gl4es-LICENSE.txt`, copied byte-for-byte from the pinned `LICENSE` (SHA-256 `51c5b405e035a85462b5211dff42b111dbcf028788327597e69b953d610e9d30`). Its copyright lines: 2016-2018 Sebastien Chevalier, 2013-2016 Ryan Hileman, 2025-2026 BZLZHH.
- **Pinned commit:** `6e153a1622a8d9ef903f7975aafbef2453571bab`

The patch changes NG-GL4ES's `CMAKE_SOURCE_DIR` and `CMAKE_PROJECT_NAME` uses so they work in a subdirectory build, builds with `-g1` instead of `-g0`, and removes NG-GL4ES's `--strip-all` link flag so the unstripped copy keeps its symbols. The file is generated by `tools/licenses/ng_gl4es_notices.py`, which refuses to finish if any notice marker has no identifiable comment block. Regenerate with `python3 tools/licenses/ng_gl4es_notices.py <ng-gl4es-source> <output> 6e153a1622a8d9ef903f7975aafbef2453571bab`. The output is deterministic, and it was reproduced byte-for-byte from the pinned source. The list below is a summary; the notice file is the authority.

## Native debug symbols (CI artifact, not in the APK)
- CI uploads the unstripped native libraries from the same build as the APK as the artifact `void-launcher-native-symbols` (kept 30 days). The APK keeps the stripped copies.
- For `libng_gl4es.so`, CI checks that the unstripped copy has a symbol table and the same GNU build-id as the APK copy. A mismatch fails the build. CI prints a warning if the APK copy still has a symbol table.
- `libgl4es_114.so` is a prebuilt file from PojavLauncher, so this project has no unstripped copy of it.

- **Source:** PojavLauncher fork, pinned commit `b32a74357b1f064193beebfe1baa12c226568353`, path `app_pojavlauncher/src/main/jniLibs/arm64-v8a/libjnidispatch.so`
- **Upstream project:** JNA (https://github.com/java-native-access/jna), dual licensed Apache-2.0 / LGPL-2.1

## JNA native dispatch library (per game version, downloaded from Maven Central)
- **Source:** the JNA project's own official Android build, published alongside the regular jar as
  `net/java/dev/jna/jna/<version>/jna-<version>.aar` on Maven Central (not a third-party rebuild).
- **License:** JNA is dual licensed Apache-2.0 / LGPL-2.1 (https://github.com/java-native-access/jna)
- **How it's used:** `JnaNatives.kt` downloads the .aar for the JNA version the running game's
  metadata requests, verifies its SHA1 against a short pinned list, and extracts
  `jni/arm64-v8a/libjnidispatch.so` into a per-version natives folder - the exact approach
  PojavLauncher's own `tasks/NativesExtractor.java` and `tasks/MoJsonDownloader.java` use
  (TeamPojavLauncher/PojavLauncher, confirmed by reading that source directly).
- **Why not keep using the static jniLibs copy:** JNA discards a native dispatch library whose
  compiled-in version does not match its own jar, so a single static copy only works for the one
  JNA version it was built against. PojavLauncher's own source documents this copy as a fallback
  that "may be too old" and always prefers a version-matched download when the game needs JNA
  5.13.0 or newer (our games need 5.17.0).
